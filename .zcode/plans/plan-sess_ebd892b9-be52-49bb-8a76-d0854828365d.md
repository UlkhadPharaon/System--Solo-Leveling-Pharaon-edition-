# AI Mentor Agent Capabilities — Implementation Plan

Give the AI Mentor (NVIDIA Nemotron `nvidia/nemotron-3.5-lightning-30b-a3b` — already tested working) the power to **create, edit, and delete things in the app** so it can personalize the experience and help on the user's journey. All existing infra (JSON-mode structured output, whitelist validation, state setters + auto-persist) will be reused.

## Core Design
- New `agentMode` flag on `POST /api/ai-coach`. When on, the LLM must reply with JSON `{ reply, actions: [...] }`.
- Server validates each action against a whitelist (mirroring the existing `validateQuests` pattern): drop/coerce bad ones, clamp XP, whitelist enums, cap string lengths.
- Client renders the proposed `actions` as **confirmation cards** (Appliquer / Ignorer / Tout appliquer) — nothing changes without user OK.
- Applied actions mutate React state via existing setters → **auto-persisted** to localStorage + cloud sync for free.

## 1. `src/types.ts` — new types
Add `AgentAction` union + payload interfaces:
- `update_personalization` (userName, userTagline, hunterTitle, dailyQuote)
- `add_schedule_block` / `delete_schedule_block` / `toggle_schedule_block` (day, title, startTime, endTime, category)
- `add_victory_log` (successes, improvements)
- `add_quest` (title, description, xpReward)
- `update_weekly_target` (targetId, minHours, maxHours)
- `add_habit_check` (domainId)
- `add_note` / `update_note` / `delete_note` (the app's "files" — notepad CRUD)
- `award_xp` (xp, gold, reason)

## 2. `server.ts` — extend `/api/ai-coach`
- Accept `agentMode?: boolean` in body.
- When agentMode: build an agent system prompt (JSON schema contract spelled out, like `QUEST_SYSTEM_PROMPT`), call `chatCompletion` with `jsonMode: true` (uses existing `response_format` support) for NIM/OpenRouter; Gemini branch gets `generationConfig: { responseMimeType: 'application/json' }` + JSON.parse fallback.
- `validateAgentActions(raw, validDomainIds)` — action-type whitelist, enum/day/category validation, `RegExp` on HH:MM times, XP clamp 5–120, string length caps, `id` generation instructions.
- Returns `{ reply, actions, source }` (backwards-compatible when agentMode is false: same as today).

## 3. `src/App.tsx` — dispatcher + context
- Add `applyAgentActions(actions)` using a switch over existing setters:
  - personalization → `setPersonalization` merge
  - schedule blocks → `setDaySchedules` (append/filter/toggle on the given day)
  - victory log → `handleAddVictoryLog`
  - quest → append to `playerProfile.dailyQuests`
  - weekly target → `setCategoryTargets` map
  - habit check → mirror `handleToggleHabitCheck` logic
  - notes → `setNotes` CRUD
  - xp → `addXPAndGoldToPlayer`
- Enrich `contextData` sent to the modal (daySchedules, notes, victoryLogs, habitChecks, playerProfile summary) so the agent can make informed proposals. Pass `onApplyActions` to `<AIAssistantModal>`.

## 4. `src/components/AIAssistantModal.tsx` — agent UI
- Parse `data.actions`; render each as a bordered "Proposition du Mentor" card showing what will change, with **Appliquer** / **Ignorer** buttons + a **Tout appliquer** bulk action. Mark applied ones ✓.
- Add a lightweight **markdown renderer** (no new deps) so Nemotron's **bold**, bullet lists, and headers display cleanly instead of raw `**` text.
- Call `onApplyActions(actions)` when user confirms.

## 5. Test & verify
- curl `/api/ai-coach` with `agentMode: true` and a prompt like "Ajoute un bloc musculation à 07:00 dimanche et note que je dois écrire une scène" → assert response contains valid `actions`.
- `npm run build` + `npx tsc --noEmit` pass.
